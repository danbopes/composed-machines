# Compound-entity patterns in the local mod library (a–m, plus source checkouts)

Scope: the latest version of each mod zip in the author's local mod library (downloaded from the mod portal) whose name
starts with a–m (113 distinct mods after de-duplicating versions), plus a few source checkouts of the mods' public
repositories. Control-stage Lua was grepped for
`create_entity`, `on_nth_tick`/`on_tick`, `proxy-container`, `linked-container`, `electric-energy-interface`,
`simple-entity-with-owner`, `fixed_recipe`, `gui.relative`, and then each hit was read by hand. Graphics-only mods
(`*-graphics`, `angels*graphics`, reskins, sound packs) and pure GUI/QoL tools were skipped quickly.
`0-things` is outside a–m but is included because cybersyn2 depends on it and it is a general compound-entity framework.
API facts were checked against the 2.1.24 API reference JSON published at lua-api.factorio.com.

## Patterns, counted

Mods in the a–m set that use each primitive in Lua (not only the ones above; some of these are libraries or GUI tools):

- `linked-container`: aai-loaders, AutoDeconstruct, Automatic_Train_Painter, bplib, chest-auto-sort, cybersyn2, EditorExtensions, FactorySearch, inserter-throughput-lib, kry_stdlib (mostly type lists)
- `proxy-container`: Cerys, cybersyn2, bplib, FilterHelper, kry_stdlib (plus SpidertronPatrols and Mining_Drones in the source checkouts)
- `electric-energy-interface`: KS_Power, Factorio-Tiberium, EditorExtensions (others are tips-and-tricks or editor tools)
- `simple-entity-with-owner`: Cerys (frozen tower base), mferrari_lib (`mf-diggy-hole`), plus orientation tables in bplib/cybersyn2
- `fixed_recipe` as a fake machine: equipment-gantry, Moshine, Cerys (4 repair/excavate recipes + solar-ghost-maker), Age-of-Production
- `raise_on_crafted` / `on_crafted_event` (2.1): **only Moshine**. Cerys does the same job by polling `products_finished` every 15 ticks
- `disabled_by_script` to freeze a host entity: aai-loaders, Cerys, equipment-gantry, cybersyn-combinator
- Relative GUIs grafted onto vanilla GUIs: loader_gui (loaders-modernized), inserter_gui (bobinserters), accumulator_gui (Cerys rod), proxy_container_gui / spider_vehicle_gui (SpidertronPatrols), plus full replacements via `player.opened = <frame>` (LTN_Combinator_Modernized, Cerys teleporter, EditorExtensions redirecting to the proxy)

Update strategies seen:

1. `on_nth_tick(N)` over the full list: aai-signal-transmission (30), equipment-gantry (60), corrundum (45, 53). Simple, but cost is O(all) every N ticks and reaction is delayed by up to N.
2. `on_tick` with manual buckets or strides: aai-loaders (scheduled tick buckets), Mining_Drones (`tick % rate`), Tiberium (`i % 60`), Cybersyn-Content-Reader (stride), LTN (state machine), IPL (load-spreader library).
3. Every tick, everything: EditorExtensions infinity wagon (fluid sync + teleport), Tiberium SRF walls, Cerys tick_1 checks.
4. Events only: Moshine (`on_crafted_event`), 0-things, cybersyn2 child chest, angels sea pump.

Libraries that exist only to make these hacks bearable are evidence in their own right: **0-things** (compound lifecycle), **load-spreader** ("spread the load of processing tasks over multiple ticks"), **item-request-proxy-events** (polling to fake a missing event), and flib/kry_stdlib/bplib event helpers.

## Capability gaps (what the engine would need)

1. **Several inventories on one entity, with inserter access rules.** equipment-gantry (3 hidden chests), Cerys module inserter (proxy into module inventory), cybersyn2 (proxy chest to read a wagon), SpidertronPatrols dock. *Part:* inventory list with names, sizes, filters and which side or offset inserters reach.
2. **Fluid fuel or fluid box on types that lack one.** aai-loaders (hidden storage tank + extraction loop), EditorExtensions wagon (infinity pipe + every-tick copy). *Part:* fluid box with a consumption rate tied to activity.
3. **Electric energy on types that lack it, with a state-change event.** aai-signal-transmission uses a roboport only to get a buffered consumer, then polls `energy`; Tiberium emitters poll `energy >= buffer`; corrundum's ice box has no power at all; the mod-portal freezer authors say a container cannot take energy and a hidden powered entity is "complicated and bug-prone". *Part:* energy source on any entity + opt-in `on_power_state_changed`.
4. **Several circuit connectors, and Lua-writable outputs.** LTN (lamp + 2 combinators per stop), AlertScanner, Cybersyn-Content-Reader, cybersyn2. *Part:* N named connectors with input/output roles; script-set output signals.
5. **Progress/completion events per prototype.** 2.1's `raise_on_crafted` covers recipes and Moshine uses it; Cerys still polls `products_finished`. A component entity needs the same opt-in for its own timer part (`on_progress_complete`), with no fake recipe.
6. **Runtime-settable parameters that today need one prototype per value.** Cerys reactors and lamps per radius, EditorExtensions accumulator per priority × mode, equipment-gantry per rotation, Tiberium hidden beacon filled with N fake modules. *Part:* parameters (radius, priority, effect bonus) that Lua can write.
7. **Spoil-rate / ambient modifiers on inventories and heat.** corrundum ice box, Cerys cooling loops. Engine has no container spoil multiplier (checked 2.1 prototype API: spoil fields exist only on items and quality); devs called a surface spoil multiplier unlikely because items do not know their surface.
8. **Compound lifecycle (ghost, blueprint, undo, rotate, move, clone).** 0-things exists to solve this; EditorExtensions teleports the proxy every tick; equipment-gantry ships extra rotated prototypes; aai-loaders re-creates the pipe if it goes missing.
9. **Script-driven visual state.** Cerys rod spawns glow/animation/lamp entities; LTN uses a lamp for its status colour.
10. **Missing native events polyfilled by polling:** item-request-proxy fulfilled, spidertron arrived at dock, circuit value changed (IPL, Content Reader).

## Candidate entities for the test mod (each maps to a real hack above)

1. **Cold box**: container + electric energy part + spoil-rate multiplier while powered (corrundum ice-box, freezer mods).
2. **Lubricated loader**: loader + fluid box consuming lubricant per item moved, stops when dry (aai-loaders).
3. **Equipment gantry**: three named inventories (grid, equipment, output) + timer part + `on_progress_complete` event to do the Lua work (equipment-gantry).
4. **Powered transceiver**: electric buffer + 2 circuit connectors (in/out) + `on_power_state_changed` (aai-signal-transmission, LTN).
5. **Repairable wreck**: timer part consuming items, opt-in completion event, state change without destroy/create (Cerys wrecks, Moshine stages).
6. **Variable-radius heater**: heat buffer + emitter whose radius Lua can set (Cerys radiative tower).
7. **Module-loading inserter target**: entity that exposes its module inventory to inserters by access rule (Cerys proxy inserters).
8. **Signal reader**: no inventories, Lua-writable output signals, ticked only while subscribed (Cybersyn-Content-Reader, AlertScanner).
9. **Infinity fluid wagon analogue**: fluid source part on a moving entity (EditorExtensions) is a stress case for part ownership.
